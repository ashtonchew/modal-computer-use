## Measurement boundaries

One coordinate click is one destination click. Modal, Daytona, and Tzafon issue one request. E2B
issues one SDK call whose pinned implementation makes two transport requests. Four coordinate
clicks are one native batch request for Modal and Tzafon, four sequential requests for Daytona, and
four SDK calls/eight pinned-SDK transport requests for E2B.

The command case requests non-login shell behavior with argv `["sh", "-c", "printf 42"]`, a
30-second timeout, and validated stdout `42`. Modal carries argv to the daemon. Daytona, E2B, and
Tzafon receive the equivalent provider command string because that is their public transport
shape. Cleanup errors are terminal in the producer; the combined artifact requires successful
command and top-level outcomes and does not make an additional cleanup claim the source schema
cannot prove.

The screenshot row uses each provider's native/default screenshot format. Tzafon returned 1280x720
JPEG while Modal, Daytona, and E2B returned 1024x768 PNG in the provider-default run. The row is
therefore API-path evidence, not a pixel- or codec-normalized visual comparison.

## Modal command decomposition

The selected 30-sample Modal command result decomposed as follows:

| Stage | p50 ms | p95 ms |
| --- | ---: | ---: |
| Total request | 13.44 | 21.37 |
| Daemon route, including process execution | 8.82 | 13.41 |
| Caller/transport overhead | 4.61 | 8.18 |

The daemon route includes process-runner admission, child creation, output handling, waiting, and
cleanup; it is not a measurement of only the shell program. A separate 10-sample-per-arm runner
study found shared-loop `asyncio` had a high tail, while `threaded` and `isolated-asyncio` were close.
The selected optimized configuration uses `isolated-asyncio`.

## Lifecycle context and evidence

Product creation runs from the product create call through a returned, decoded, parsed, and
validated full-screen image. Provider startup models differ: Modal includes its image, daemon, and
configured ingress; the other products use their public managed creation paths. Requested region
placement is recorded but not independently attested to a physical availability zone.
